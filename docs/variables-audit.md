## Summary of Patterns

1. **`organizationId`** is hardcoded to `'org-1'` in 3 places: `ingestion.controller.ts`, `plugin-context.service.ts`, and noted in `AGENTS.md`. This is a known temporary measure until auth lands.

2. **Two config bypasses**: `insight-extraction.capability.ts` reads `LLM_MAX_RETRIES` and `OWNER_RESOLVER_MAX_DISTANCE` directly from `process.env`, sidestepping NestJS config system defaults.

3. **Config default mismatch**: `OWNER_RESOLVER_MAX_DISTANCE` default is `3` in `llm.config.ts` but `'1'` (string) in `insight-extraction.capability.ts`.

4. **Session secret** in `main.ts` is hardcoded (`'pn-console-dev-session-secret'`) — should come from env in production.

5. **Telegram datacenter IPs** are hardcoded in `telegram-client.factory.ts`.

6. **Local file store** for Telegram topic mappings uses `~/.pn-console/plugins/telegram/` — assumes POSIX home directory.

7. **Swagger metadata** (`'PN Console API'`, `'0.0.1'`, etc.) is hardcoded in `main.ts`.

8. **LLM system prompt** is fully hardcoded in `insight-extraction-prompt.ts` — any prompt tuning requires code change.
